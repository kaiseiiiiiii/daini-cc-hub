# チェックリスト

掲示板の投稿に**期日**と**メンバーごとの完了チェック**を付ける機能です。
スプレッドシートで「項目×人のチェック表」を管理していたものを、アプリ側に移しました。

---

## 設定は要りません

アプリ側のチェックリストは、**セキュリティルールを公開すればすぐ使えます。**
掲示板に投稿するとき「期日」を入れれば、その投稿がチェックリストになります。

任意で足せるものが1つあります。

| 足すもの | 何が起きるか | 必要なもの |
|---|---|---|
| 期日リマインド | 毎朝、期日が近い／過ぎている未完了が Chat に流れる | Chat の Webhook（新着通知と同じもの） |

> **Google カレンダー連携は入れていません。**
> 理由は下の「カレンダー連携について」を読んでください。

---

## 使い方

### チェックリストを作る

1. 掲示板タブ → 「+ 掲示板に投稿する」
2. タイトルと内容を書く
3. **「📅 期日」に日付を入れる** ← これを入れた投稿がチェックリストになります
4. 全員が対象でよければそのまま投稿。特定の人だけにしたいときは
   「対象者を選ぶ」を開いて、外す人のチェックを外します

期日を入れなければ、これまでどおりの連絡事項です。何も変わりません。

### 完了にする

投稿の中の「完了にする」を押すだけです。もう一度押すと取り消せます。

- **押せるのは自分の分だけです。** 他人を完了にすることはできません
  （管理者でもできません。セキュリティルールで禁止しています）
- 「完了 5/15名」を押すと、**まだ終わっていない人の名前**が出ます
- 掲示板の先頭に「**あなたの未完了 ◯件**」が出ます。期日の近い順です

```
┌────────────────────────────────────┐
│ ✅ あなたの未完了 3件              │
│ ─────────────────────────────────  │
│ [ ] 本日締めの提出物         本日  │
│ [ ] 1班だけ対象のタスク    残り2日 │
│ [ ] 8月アップデート        残り4日 │
└────────────────────────────────────┘
```

期日が2日以内のものは色が変わり、過ぎているものは赤で「期限切れ」と出ます。

### 画像を添付する

投稿フォームの「🖼 画像を添付する」から選べます。1投稿につき1枚です。
編集から差し替え・取り外しもできます。

- **端末側で縮小してから送ります**（長辺 1280px の webp）。
  スクリーンショットの文字が読める程度を残しつつ、1枚が重くならない大きさです
- 投稿の中では幅520pxまでで表示し、押すと拡大表示になります（Esc か背景で閉じる）
- Chat の新着通知には **📎 だけ**が付きます。画像そのものは送りません
  （画像の中身が社外へ転送されうる経路を作らないため）

> **画像は掲示板の一覧とは別に保存しています。**
> 掲示板はログイン中ずっと購読しているので、画像を投稿と同じ場所に入れると
> タブを開くたびに全員が全部の画像を受け取ることになります。
> 実際に画面に入った画像だけを1枚ずつ読むようにしてあります。

### 期日や対象者を直す

投稿の「編集」から直せます。**編集で他人の完了記録は消えません。**
期日を消すとチェックリストではなくなりますが、完了の記録自体は残ります
（期日の消し忘れを直したときに、みんなのチェックが消えると事故になるため）。

> **対象者を後から変えたとき**
> 対象から外した人の完了記録は残りますが、集計には出ません。
> 後から対象に戻せば、その人のチェックはそのまま復活します。

## 必須の作業: セキュリティルールを公開する

**これをしないと「完了にする」を押しても失敗します。**

[`firestore.rules`](../firestore.rules) の**全文**を Firebase コンソールの
Firestore Database → ルール に貼り付けて「公開」してください。

**一部だけ書き換えず、ファイルの中身を全部置き換えてください。**
部分的に直すと括弧が合わなくなります。

押しても `permission-denied` と出る場合は、ここが古いままです。

## 任意: 期日リマインド（Chat）

毎朝、期日が近い／過ぎている未完了を Chat のスペースに流します。

```
*チェックリストの期日*

⚠️ 期限切れ（1件）
• 棚卸しの確認（3日超過） — 未完了 2名: ◯◯・◯◯

📅 本日まで（1件）
• 8月アップデート — 未完了 4名: ◯◯・◯◯・◯◯・◯◯

第二CC Hub で完了にする
```

### 手順1: コードを貼る

Apps Script（`sync.gs` / `notify.gs` を置いてあるプロジェクト）を開きます。

左の **＋ → スクリプト** で新しいファイルを作り、名前を `tasks` にします。
中身を [`gas/tasks.gs`](../gas/tasks.gs) の**全文**にします。

`notify.gs` も更新してください（新着通知に期日を出すようにしました）。
こちらも**ファイルの中身を全部消して貼り直してください。**

必要なスクリプトプロパティは `CHAT_WEBHOOK_URL` と `FIREBASE_PROJECT_ID` の2つで、
どちらも新着通知の設定で既に入っているはずです。
入っていなければ [`sync-setup.md`](sync-setup.md) を見てください。

### 手順2: 動作を確認する

上の関数選択で `checkTaskSetup` を選んで **▶ 実行**します。

```
OK      スクリプトプロパティ CHAT_WEBHOOK_URL
OK      スクリプトプロパティ FIREBASE_PROJECT_ID
OK      掲示板 12件／チェックリスト 3件（未完了が残っているもの 2件）
未設定  トリガー remindDueTasks
```

次に `remindDueTasks` を手で実行すると、文面がすぐ届きます。
促す対象が無ければ何も送りません（`_task_log` に理由が残ります）。

### 手順3: トリガーを入れる

`installTaskTriggers` を選んで **▶ 実行**します。1度だけでよいです。
`remindDueTasks` が毎日9時台に走るようになります。

もう一度 `checkTaskSetup` を実行して、トリガーが `OK` になったことを確認してください。

### 鳴る条件

| 状態 | 鳴るか |
|---|---|
| 期日が明日 | 鳴る |
| 期日が本日 | 鳴る |
| 期日を過ぎて7日まで | 鳴る（「◯日超過」付き） |
| 期日を過ぎて8日以上 | 鳴らない |
| 対象者全員が完了 | 鳴らない |
| 期日が2日以上先 | 鳴らない |

期限切れを無期限に鳴らさないのは、諦められたタスクが毎朝ノイズとして
残り続けると、リマインド自体が読まれなくなるからです。
7日は `tasks.gs` の `OVERDUE_REMIND_DAYS` で変えられます。
時刻は `REMIND_HOUR` です（変えたら `installTaskTriggers` を実行し直してください）。

### 催促が来ないとき

`whyNoRemind` を実行してください。チェックリストの一覧と、
それぞれが催促の対象かどうかが理由付きで出ます。

```
本日: 2026-08-14／催促は毎日 9時台、期限切れは 7日まで

  2026-08-14  本日締めの提出物  → ★ 本日まで（未完了 2名: ◯◯・◯◯）
  2026-08-18  8月アップデート    → まだ 4日あるため対象外（未完了 10名: ...）
  2026-08-01  古いタスク         → 13日超過。7日を過ぎたため対象外（未完了 1名: ◯◯）
```

実行の履歴は同期用スプレッドシートの `_task_log` タブに残ります（直近500件まで）。

## カレンダー連携について

**入れていません。** 「期日に全員へカレンダー通知が自動で飛ぶ」を
素直に実現する方法が無いためです。

専用カレンダーを1つ作ってみんなで相乗りする方式では、
**作った側が付けた通知が、見ている人には届きません。**
自分が持っていないカレンダーの通知をどうするかは、
Google カレンダーの仕様上「見ている人それぞれの設定」になります。
つまり「カレンダーを開けば予定が見える」だけで、期日にポップアップは鳴りません。

全員に確実に鳴らすには、次のどちらかが必要です。

| 方法 | 代償 |
|---|---|
| 予定に全員をゲストとして追加する | 作成・日付変更・削除のたびに招待メールが15人全員に飛ぶ |
| 各メンバーが自分のカレンダー設定で、そのカレンダーの通知を1度だけ入れる | 設定していない人には鳴らない。しかも本人が「鳴っていない」ことに気づけない |

どちらを取るかが決まっていないため、いまは**気づかせる役割を Chat に任せています。**
Chat は設定作業もメールも無しで、確実に全員に届きます。

必要になったら足せます。データ構造は変えずに済みます
（GAS 側の処理を1つ増やすだけです）。

なお、サービスアカウントで人のカレンダーに書く方式は採りません。
それには「ドメイン全体の委任」が必要で、
**全社員のカレンダーを代理操作できる鍵**を作ることになります。
チェックリストのために持つ権限としては過大です。

## データの形

`boardPosts/{id}` に、チェックリストとして使うときだけ次のフィールドが付きます。
**付いていない投稿が正常にあります**（ふつうの連絡事項、およびこの機能より前の投稿）。

| フィールド | 型 | 意味 |
|---|---|---|
| `dueDate` | string \| null | `"YYYY-MM-DD"`。入っているとチェックリストになる |
| `checkTargets` | array \| null | 対象者の memberId。**null は「全員」** |
| `doneBy` | map | `{memberId: 完了した日時}` |
| `imageId` | string \| null | `boardImages` のドキュメントID |
| `imageW` / `imageH` | number \| null | 読み込み前に縦横比の箱を置くための寸法 |

画像そのものは `boardImages/{自動ID}` に入ります。

| フィールド | 型 | 意味 |
|---|---|---|
| `authorId` | string | 貼った人の memberId |
| `dataUrl` | string | `data:image/webp;base64,...`（900,000文字未満） |
| `width` / `height` | number | 縮小後の寸法 |
| `createdAt` | timestamp | 作成日時 |

寸法を投稿側にも持たせているのは、**画像を取りに行く前に縦横比の箱を置く**ためです。
あとから高さが決まると、読んでいる途中の文章が下にずれて視線が飛びます。

`dataUrl` の上限は Firestore の1ドキュメント上限（約1MiB）から来ています。
画像だけで枠を使い切ると、同じドキュメントの本文や完了記録が書けなくなるため、
余裕を残して止めています。アプリ側の `BOARD_IMG_MAX` とルール側の値は同じです。

**画像は差し替え・削除ができません**（ルールで `update, delete: if false`）。
差し替えは新しいドキュメントを作り、投稿側の参照だけを移します。
「あの画像は誰がいつ貼ったか」を後から追えるようにするためで、
投稿の論理削除と同じ考え方です。

> **その代わり、参照されない画像が残ります。**
> 差し替えや取り外しをした分だけ溜まっていきます。画面には出ませんが、
> メンバーであれば読める状態で残る点に注意してください。
> 1枚あたり最大約900KB、Firestore の無料枠は1GiB なので、
> この規模では容量が問題になるより先に運用が変わるはずです。
> 気になる場合は、参照の無い `boardImages` を GAS でまとめて消す処理を
> 足せます（サービスアカウントはルールを迂回できるため）。

`checkTargets` に「全員」を列挙して保存しないのは、
**後から入った人が過去のタスクの対象から抜け落ちる**からです。
`null` のままにしておけば、その時点の在籍メンバーが常に対象になります。

`doneBy` を memberId をキーにしたマップで持つのは、
セキュリティルールで**各自を自分のキーだけに縛れる**形がこれだからです。
逆向き（完了者の配列）にすると、ルール言語には動的キーの取り出しもループも無いため
「他人の完了を消していないこと」を検証できません。

`dueDate` を Timestamp ではなく文字列で持つのは、時刻もタイムゾーンも
意味を持たない「日付」であり、Timestamp にすると時差で1日ずれる事故が
起きるためです。
