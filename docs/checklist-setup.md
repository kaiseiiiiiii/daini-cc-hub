# チェックリストとカレンダー連携のセットアップ

掲示板の投稿に**期日**と**メンバーごとの完了チェック**を付ける機能です。
期日は Google カレンダーの専用カレンダーに終日予定として出て、
期日の前日・当日・超過時には Google Chat のスペースに未完了者が流れます。

---

## まず「連携なしで」使えます

アプリ側のチェックリストは、**カレンダーの設定をしなくてもそのまま使えます。**
掲示板に投稿するとき「期日」を入れれば、その投稿がチェックリストになります。

このドキュメントの設定が必要なのは、次の2つを足すときだけです。

| 足すもの | 何が起きるか | 必要なもの |
|---|---|---|
| カレンダー連携 | 期日が Google カレンダーに終日予定で出る | 専用カレンダー1つ＋スクリプトプロパティ |
| 期日リマインド | 毎朝、期日が近い／過ぎている未完了が Chat に流れる | Chat の Webhook（通知機能と同じもの） |

---

## 使い方（アプリ側）

### チェックリストを作る

1. 掲示板タブ → 「+ 掲示板に投稿する」
2. タイトルと内容を書く
3. **「📅 期日」に日付を入れる** ← これを入れた投稿がチェックリストになります
4. 全員が対象でよければそのまま投稿。特定の人だけにしたいときは
   「対象者を選ぶ」を開いて、外す人のチェックを外します

期日を入れなければ、これまでどおりの連絡事項です。何も変わりません。

### 完了にする

投稿の中の「完了にする」を押すだけです。もう一度押すと取り消せます。

- **押せるのは自分の分だけです。** 他人を完了にすることはできません
  （管理者でもできません。セキュリティルールで禁止しています）
- 「完了 5/15名」を押すと、**まだ終わっていない人の名前**が出ます
- 掲示板の先頭に「あなたの未完了 ◯件」が出ます。期日の近い順です

### 期日や対象者を直す

投稿の「編集」から直せます。**編集で他人の完了記録は消えません。**
期日を消すとチェックリストではなくなりますが、完了の記録自体は残ります
（期日の消し忘れを直したときに、みんなのチェックが消えると事故になるため）。

> **対象者を後から変えたとき**
> 対象から外した人の完了記録は残りますが、集計には出ません。
> 後から対象に戻せば、その人のチェックはそのまま復活します。

---

## 手順1: 専用カレンダーを作る

**既存のカレンダー（自分の予定表など）は使わないでください。**
共有範囲を間違えたときの影響が大きく、個人の予定と混ざります。

1. Google カレンダー → 左下の「他のカレンダー」の **＋** → 「新しいカレンダーを作成」
2. 名前: `第二CC 期日` など
3. タイムゾーン: **（GMT+09:00）日本標準時**
4. 「カレンダーを作成」

### 共有する

作ったカレンダーの「設定と共有」を開きます。

1. 「特定のユーザーやグループと共有する」→ メンバーを追加
   - 権限は **「予定の表示（すべての予定の詳細）」** にしてください
   - **「予定の変更」は不要です。** アプリが正なので、カレンダー側で直されると
     アプリの期日とずれます
2. メンバーは自分のカレンダーで、このカレンダーを表示に切り替えます

> ⚠️ **このカレンダーを第二CC以外に共有しないでください。**
> 掲示板のタイトルがそのまま予定名になります。
> 「組織全体で利用できるようにする」や「一般公開して誰でも利用できるようにする」は
> 絶対に有効にしないでください。

### カレンダーIDを控える

同じ「設定と共有」の画面を下にスクロールすると
**「カレンダーの統合」→「カレンダー ID」**があります。
`xxxxxxxx@group.calendar.google.com` の形の文字列です。これをコピーします。

---

## 手順2: スクリプトプロパティを設定する

Apps Script（`sync.gs` / `notify.gs` を置いてあるプロジェクト）を開きます。

**⚙ プロジェクトの設定 → スクリプト プロパティ → プロパティを追加**

| プロパティ | 値 |
|---|---|
| `TASK_CALENDAR_ID` | 手順1で控えたカレンダーID |

`CHAT_WEBHOOK_URL` と `FIREBASE_PROJECT_ID` は通知機能で既に入っているはずです。
入っていなければ [`sync-setup.md`](sync-setup.md) を見てください。

---

## 手順3: コードを貼る

Apps Script の左の **＋ → スクリプト** で新しいファイルを作り、
名前を `tasks` にします。中身を [`gas/tasks.gs`](../gas/tasks.gs) の**全文**に置き換えます。

`notify.gs` も更新してください（新着通知に期日を出すようにしました）。
**部分的に直さず、ファイルの中身を全部消して貼り直してください。**
一部だけ書き換えると括弧が合わなくなります。

---

## 手順4: 動作を確認する

上の関数選択で `checkTaskSetup` を選んで **▶ 実行**します。
初回はカレンダーへのアクセス許可を求められるので承認してください。

```
OK      スクリプトプロパティ TASK_CALENDAR_ID
OK      スクリプトプロパティ CHAT_WEBHOOK_URL
OK      カレンダー「第二CC 期日」に書けます
OK      掲示板 12件／チェックリスト 3件（カレンダー連携済み 0件）
未設定  トリガー syncTaskCalendar
未設定  トリガー remindDueTasks
```

「カレンダーが見つかりません」と出る場合、IDが違うか、
そのカレンダーが**実行しているアカウントのもの**になっていません。

次に `syncTaskCalendar` を選んで **▶ 実行**します。
カレンダーを開いて、期日の日に予定が出ていれば成功です。

---

## 手順5: トリガーを入れる

`installTaskTriggers` を選んで **▶ 実行**します。1度だけでよいです。

| 関数 | 間隔 | 役割 |
|---|---|---|
| `syncTaskCalendar` | 15分おき | 期日をカレンダーに反映する |
| `remindDueTasks` | 毎日9時台 | 未完了を Chat に流す |

もう一度 `checkTaskSetup` を実行して、トリガー2つが `OK` になったことを確認してください。

リマインドの文面をすぐ見たいときは `remindDueTasks` を手で実行してください。
促す対象が無ければ何も送りません（`_task_log` に理由が残ります）。

## 仕組み

```
アプリ（掲示板に期日を入れて投稿）
   ↓
Firestore  boardPosts/{id}  dueDate, checkTargets, doneBy
   ↓                              ↑
   ├─ syncTaskCalendar（15分おき）─┘ 予定IDを書き戻す
   │     ↓
   │  Google カレンダー「第二CC 期日」に終日予定
   │
   └─ remindDueTasks（毎朝）
         ↓
      Google Chat のスペースに未完了者
```

### なぜサービスアカウントでカレンダーに書かないのか

サービスアカウントは、**ドメイン全体の委任**を設定しない限り人のカレンダーに
書けません。委任は「全社員のカレンダーを代理操作できる鍵」を作ることで、
チェックリストのために持つ権限としては過大です。

そのため、カレンダーへの書き込みは**スクリプトの所有者の権限**で行い、
専用カレンダー1つだけに限定しています。
Firestore の読み書きは今までどおりサービスアカウントです。

### 予定の作り直しについて

予定を作ると、その**予定ID** を Firestore の投稿に書き戻します。
「作ったかどうか」をカレンダーの検索で判定していないのは、
同じ名前の予定を人が手で作ったときに取り違えるからです。

- カレンダーから予定を手で消した → 次の同期で**作り直されます**
- 投稿を削除した／期日を消した → 予定も**消えます**
- 投稿のタイトルや期日を直した → 予定も**直ります**

カレンダー側で予定名や日付を直しても、次の同期でアプリ側の値に戻ります。
**アプリが正**です。

### リマインドが鳴る条件

| 状態 | 鳴るか |
|---|---|
| 期日が明日 | 鳴る |
| 期日が本日 | 鳴る |
| 期日を過ぎて7日まで | 鳴る（「◯日超過」付き） |
| 期日を過ぎて8日以上 | 鳴らない |
| 対象者全員が完了 | 鳴らない |
| 期日が2日以上先 | 鳴らない |

期限切れを無期限に鳴らさないのは、諦められたタスクが毎朝ノイズとして
残り続けると、リマインド自体が読まれなくなるからです。
7日は `tasks.gs` の `OVERDUE_REMIND_DAYS` で変えられます。

## うまくいかないとき

### カレンダーに出ない

`whyNoCalendar` を実行してください。チェックリストの一覧と、
それぞれが連携済みかどうかが出ます。

```
カレンダー: 第二CC 期日

  2026-08-18  8月アップデート  → 連携済み
  2026-08-20  棚卸しの確認      → ★ 未連携（次の syncTaskCalendar で作られます）
```

「期日が入っている投稿が1件もありません」と出る場合は、
アプリ側で期日を入れずに投稿しています。編集で期日を足してください。

### 同じ予定が2つできた

予定IDの書き戻しが失敗すると起きます。`relinkAllTaskEvents` を実行すると
紐付けを全部外して予定を消すので、その後 `syncTaskCalendar` で作り直してください。

### 完了にできない（`permission-denied`）

セキュリティルールが古いままです。
[`firestore.rules`](../firestore.rules) の**全文**を Firebase コンソールの
Firestore Database → ルール に貼り付けて「公開」してください。
**一部だけ書き換えず、全部を置き換えてください。**

### 実行の履歴を見たい

同期用スプレッドシートの `_task_log` タブに1行ずつ残ります
（直近500件まで）。Apps Script の実行ログは流れていくので、
成否の履歴はこちらを見てください。

## データの形

`boardPosts/{id}` に、チェックリストとして使うときだけ次のフィールドが付きます。
**付いていない投稿が正常にあります**（ふつうの連絡事項、およびこの機能より前の投稿）。

| フィールド | 型 | 意味 |
|---|---|---|
| `dueDate` | string \| null | `"YYYY-MM-DD"`。入っているとチェックリストになる |
| `checkTargets` | array \| null | 対象者の memberId。**null は「全員」** |
| `doneBy` | map | `{memberId: 完了した日時}` |
| `calendarEventId` | string \| null | GAS が作った予定のID。クライアントからは書けない |

`checkTargets` に「全員」を列挙して保存しないのは、
**後から入った人が過去のタスクの対象から抜け落ちる**からです。
`null` のままにしておけば、その時点の在籍メンバーが常に対象になります。

`dueDate` を Timestamp ではなく文字列で持つのは、時刻もタイムゾーンも
意味を持たない「日付」であり、Timestamp にすると時差で1日ずれる事故が
起きるためです。GAS もこの文字列をそのまま終日予定の日付に使います。
