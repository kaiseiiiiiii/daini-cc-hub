# スプレッドシート同期のセットアップ

シフト・生産性KPI・目標／実績を、会社のスプレッドシートから Firestore へ
1時間おきに取り込む仕組みです。

---

## 構成

```
シフト_CC          ─┐
生産性データ         ├─ IMPORTRANGE ─→ 同期用スプレッドシート ─→ GAS ─→ Firestore ─→ アプリ
手配粗利額データ   ─┘   （読み取り専用）      （自分が所有）
```

**原本には一切書き込みません。** 原本から値を引くのは `IMPORTRANGE` で、これは
読み取りしかできない関数です。GAS は自分が乗っている同期用スプレッドシートしか
見ておらず、原本のファイルIDはコードのどこにも登場しません。書き込む経路が
仕組みとして存在しない構成です。

原本の所有者には**閲覧権限だけ**をもらってください。編集権限は不要です。

### この構成の弱点

`IMPORTRANGE` の値は最大30分ほど遅れることがあります（Google 側の更新間隔）。
1時間おきの同期なので実用上は問題になりませんが、「たった今スプレッドシートに
入れた数字」がすぐには反映されない点は把握しておいてください。

また、権限が切れると `#REF!` になります。その場合 GAS は**書き込まずに中断**し、
アプリ側には「同期が止まっている」警告が出ます。古い数字が最新の顔をして
残り続けることはありません。

## 手順1: サービスアカウントを作る

Firebase コンソールの「新しい秘密鍵の生成」でも動きますが、その鍵は編集者権限を
持っていて強すぎます。**必要最小限の権限だけを持つ専用アカウント**を作ります。

1. https://console.cloud.google.com/iam-admin/serviceaccounts?project=daini-cc-hub
2. 「サービス アカウントを作成」
   - 名前: `daini-cc-hub-sync`
3. ロールを選択 → **「Cloud Datastore ユーザー」**（`roles/datastore.user`）**だけ**
   - Firestore の読み書きのみ。認証・課金・他のGCPリソースには一切触れません
4. 作成後、そのアカウントを開く → 「キー」タブ → 「鍵を追加」→ 「新しい鍵を作成」→ **JSON**
5. ダウンロードされた JSON ファイルを開いて、**中身を全部コピー**

> ⚠️ **この JSON は本物の秘密鍵です。**
> `firebase-config.js` の apiKey とは性質がまったく違います。
> この鍵があれば**セキュリティルールを完全に無視して**全データを読み書きできます。
> リポジトリにも、チャットにも、メールにも貼らないでください。
> 次の手順で GAS のスクリプトプロパティに直接貼り付けたら、
> ダウンロードしたファイルは削除してください。

## 手順2: 同期用スプレッドシートを作る

Google ドライブで新しいスプレッドシートを作り、`第二CC Hub 同期用` などの名前にします。
**所有者は自分**にしてください。

### タブを10個作る

| タブ名 | 中身 |
|---|---|
| `cfg` | 原本のファイルID |
| `shift_prev` | 前月のシフト |
| `shift_cur` | 当月のシフト |
| `shift_next` | 翌月のシフト |
| `productivity` | 生産性KPI |
| `goal_all` | 手配粗利額（全体） |
| `goal_team_a` | 手配粗利額（チームA） |
| `goal_team_b` | 手配粗利額（チームB） |
| `goal_other` | 手配粗利額（その他） |
| `_log` | 実行ログ（GASが自動で作るので手動作成は不要） |

### `cfg` タブ

原本のURLから ID を取り出して入れます。URL の
`https://docs.google.com/spreadsheets/d/【ここがID】/edit` の部分です。

| | A | B |
|---|---|---|
| 1 | シフトのファイルID | `（シフト_CC の ID）` |
| 2 | 生産性のファイルID | `（生産性データ の ID）` |
| 3 | 手配粗利額のファイルID | `（手配粗利額データ の ID）` |
| 4 | 全体のタブ名 | `全体Daily集計` |
| 5 | チームAのタブ名 | `（チームAのタブ名）` |
| 6 | チームBのタブ名 | `（チームBのタブ名）` |
| 7 | その他のタブ名 | `その他` |

> B5・B6 に入れるタブ名はリーダーの姓です。**このリポジトリは公開されている**ため、
> 実際の名前は手順書に書かず、シート側に置いています。
> 手配粗利額データを開いて、タブ名をそのままコピーしてください。

### 各タブの A1 に入れる式

**`shift_cur`**（当月。月が変わると自動で切り替わります）

```
=IMPORTRANGE(cfg!B1, YEAR(TODAY())&"_"&MONTH(TODAY())&"!A1:AH70")
```

**`shift_prev`**（前月）

```
=IMPORTRANGE(cfg!B1, YEAR(EDATE(TODAY(),-1))&"_"&MONTH(EDATE(TODAY(),-1))&"!A1:AH70")
```

**`shift_next`**（翌月。まだ作られていなければ `#REF!` になりますが、それで正常です）

```
=IMPORTRANGE(cfg!B1, YEAR(EDATE(TODAY(),1))&"_"&MONTH(EDATE(TODAY(),1))&"!A1:AH70")
```

**`productivity`**

```
=IMPORTRANGE(cfg!B2, "生産性　集計!A1:M60")
```

> シート名の「生産性」と「集計」の間は**全角スペース**です。半角だと `#REF!` になります。

**`goal_all` / `goal_team_a` / `goal_team_b` / `goal_other`**

タブ名は `cfg` から引くので、この4つはそのまま貼り付けられます。

```
=IMPORTRANGE(cfg!B3, cfg!B4&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B5&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B6&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B7&"!A1:K40")
```

### アクセスを許可する

式を入れた直後は `#REF!` と表示され、セルにカーソルを合わせると
「アクセスを許可」ボタンが出ます。**原本3件それぞれで1回ずつ**押してください。
一度許可すれば、以降は自動で更新されます。

`shift_next` だけは、原本に翌月のシートがまだ無ければ `#REF!` のままです。
これは異常ではありません。

## 手順3: GAS を設置する

1. 同期用スプレッドシートで **拡張機能 → Apps Script**
2. 既定の `コード.gs` の中身を全部消し、リポジトリの
   [`gas/sync.gs`](../gas/sync.gs) の中身を貼り付ける
3. 保存

### スクリプトプロパティを設定する

エディタ左の **⚙ プロジェクトの設定** → 一番下の「スクリプト プロパティ」

| プロパティ名 | 値 |
|---|---|
| `FIREBASE_PROJECT_ID` | `daini-cc-hub` |
| `FIREBASE_SERVICE_ACCOUNT` | 手順1でコピーした JSON **全文**（`{` から `}` まで） |

**この2つ以外に設定は必要ありません。** 鍵も原本のIDも、コード側には一切書きません。

### 動作を確認する

エディタ上部の関数選択で **`checkSetup`** を選んで実行します。
初回は Google の権限確認が出るので許可してください。

「実行ログ」に次のように出れば設定完了です。

```
OK     スクリプトプロパティ FIREBASE_PROJECT_ID
OK     スクリプトプロパティ FIREBASE_SERVICE_ACCOUNT
OK     タブ cfg  3行
OK     タブ shift_prev  67行
OK     タブ shift_cur  67行
#REF!  タブ shift_next（原本にその月が無い場合は正常）
OK     タブ productivity  20行
OK     タブ goal_all  33行
...
OK     アクセストークン取得
OK     members 15名を取得
```

### 手動で1回동かす

**`manualSync`** を実行します。エラーが出なければ、Firestore の
`shifts` / `metrics` / `goals` / `syncStatus` にデータが入ります。
アプリのシフトタブ・実績タブを開いて表示を確認してください。

### トリガーを設定する

**`installTrigger`** を1回だけ実行します。毎時のトリガーが作られます。

Google の仕様上「毎時0分ちょうど」には走らず、その時間内のどこかで実行されます。
時間帯の判定（10時台〜22時台）はコード側で行っているので問題ありません。

## 同期の時間帯

| 時刻 | 動き |
|---|---|
| 0時〜9時台 | 何もしない（実績が動かない時間帯。叩いても同じ数字を取り直すだけ） |
| 10時台 | その日の最初の同期 |
| 11時〜21時台 | 毎時同期 |
| 22時台 | **当日分の締め。**実績の最終更新が21時30分なので、これが確定値 |
| 23時台 | 何もしない |

範囲外の時刻ではトリガーは起動しますが、時刻を見て即座に終了します。
ログにも残しません（毎日11行の無意味な行が増えるだけなので）。

## 同期が止まったときの見え方

アプリのシフトタブと実績タブに、状態に応じた表示が出ます。

| 状況 | 表示 |
|---|---|
| 正常 | `最終更新 8月7日 14時00分` |
| 10時台で、まだ本日分が同期されていない | 🕙 前日の数字を表示中です。本日分の同期はこれから行われます |
| 11時以降で、本日一度も同期されていない | ⚠️ 本日まだ一度も同期されていません。数字は前日のものです |
| 稼働時間帯で最終更新から3時間以上経過 | ⚠️ 最終更新から◯時間が経過しています |
| 前回の同期が失敗した | ⚠️ 前回の同期が失敗しています |
| 深夜・早朝 | 警告なし（同期しない設計のため） |

**深夜に警告を出さないのが要点です。** 単純な経過時間だけで判定すると、
朝は必ず「12時間更新されていません」と出てしまい、誰も見なくなります。

アプリを開きっぱなしにしていても、5分おきに状態を見直して表示を切り替えます。

## トラブル時の確認場所

**1. 同期用スプレッドシートの `_log` タブ**

実行時刻・結果・所要時間・処理件数・エラー内容が1行ずつ残ります（直近500件）。

| 列 | 内容 |
|---|---|
| 未照合の氏名 | シフト表にいるがメンバーマスタと一致しなかった人数。第二CC以外の拠点の人は当然ここに入るので、0でなくて正常です |

**2. Apps Script の「実行数」画面**

失敗した実行のスタックトレースが見られます。

**3. Firestore の `syncStatus/spreadsheet`**

最終同期時刻、成否、エラー内容、未照合だった氏名の一覧が入っています。

### よくある原因

| 症状 | 原因 |
|---|---|
| `IMPORTRANGE が解決できていません` | 原本の閲覧権限が切れた、または「アクセスを許可」を押していない |
| `members が1件も取得できませんでした` | サービスアカウントのロール不足。Cloud Datastore ユーザーが付いているか確認 |
| 特定の人だけ実績が出ない | メンバーマスタの `fullName` がスプレッドシートの表記と一致していない。`syncStatus` の `unmatchedNames` を確認 |
| `アクセストークンの取得に失敗` | `FIREBASE_SERVICE_ACCOUNT` の JSON が途中で切れている |

## メンバー別KPI（チームタブ・任意）

「チーム」タブに出すメンバー別の **対応数・手配数・手配率・手配粗利額** を
取り込みます。通話率・作業率は既存の `productivity` タブから来るので、
ここでは扱いません。

> ⚠️ このデータは**全メンバーには見せません**。誰が何件・いくら手配したかが
> 一覧で並ぶため、`firestore.rules` で `canSeeTeamKpi` を持つ人だけに
> 読み取りを限定しています。画面で隠すだけでは、開発者ツールから取れて
> しまうので意味がありません。

### 手順1: ファイルIDを `cfg` に足す

`cfg` タブの **B8** に Management Sheet のファイルIDを入れます
（他の原本と同じく、IDはコードにも手順書にも書きません）。

**B1〜B7 はすでに使われています**（原本3件のファイルIDと、チーム4つのタブ名）。
空いている行から始めてください。上書きすると `goal_team_a` などの
既存の IMPORTRANGE が壊れます。

| セル | 中身 |
|---|---|
| `cfg!B8` | Management Sheet のファイルID |
| `cfg!B11` | 月別タブの**接頭辞**（例 `21th_`）。下記参照 |

### 手順2: `mgmt_kpi` タブを作る

同期用スプレッドシートに `mgmt_kpi` という名前のタブを追加し、A1 に貼ります。

```
A1 と C1 に、**別々の式**として入れます。

**A1**
```
=IMPORTRANGE(cfg!B8, cfg!B11&MONTH(TODAY())&"月!A1:B40")
```

**C1**
```
=IMPORTRANGE(cfg!B8, cfg!B11&MONTH(TODAY())&"月!AE1:AV40")
```

1つの式に `{ }` でまとめないでください。Management Sheet は7MBあり、
2範囲を一度に読むと「インポート範囲の内部エラー」で失敗します。
別セルに分ければ、片方が失敗してももう片方は生きます。

### タブ名の接頭辞を `cfg!B11` に出す理由

原本の月別タブは `21th_8月` `21th_7月` `20th_6月` のように、
**期（21th）＋月**で名前が付いています。以前は `2026年8月` という
タブがあり、そちらを見ていました。

期の部分を式に直書きすると、期が変わる年に必ず壊れます。かといって
期を自動計算しようとすると、期の切り替わり月をコードが知っている
必要が出てきます。**月は `TODAY()` から自動、期だけ手で1回**という
分け方にしてあります。

期が変わったら `cfg!B11` の1セルだけ直してください。
```

原本は月ごとにシートが分かれているので、シフトと同じく `TODAY()` から
タブ名を組みます。**月が変わると自動で切り替わります。**

2つの範囲を `{ }` で横に並べているのは、両方が必要だからです。

| 範囲 | 何のため |
|---|---|
| `A1:B60` | KPI のラベル（`対応数` `手配数` `手配率` `手配粗利額`）が B列にあります |
| `AE1:AV60` | 第二CC のブロック。拠点・チーム・メンバーの列が並びます |

### なぜ位置ではなく文字で探すのか

GAS は行番号も列番号も見ていません。**氏名とラベルの文字**で場所を決めます。

- 列は `members` の `fullName` と一致した列だけ拾います
- 行は KPI のラベルと一致した行だけ拾います

そのため原本の列が増減しても動きます。また `東京第二CC` `野ざらし` `ユニゾン`
`第二東京その他` といった**集計列は氏名と一致しないので自動的に除外**されます。
チームの括りが原本側で変わっても、アプリの集計には影響しません。

逆に、**氏名の表記が変わると拾えなくなります**。`members` の `fullName` と
原本の氏名（姓名の間のスペースを除いて）は一致させておいてください。
照合できた人数は次の手順で確認できます。

### 手順3: 動作確認

`manualSync` を実行し、`syncStatus/spreadsheet` の `mgmtMemberCount` が
人数ぶん入っていれば成功です。0 のままなら、氏名が1人も照合できていません。

### 手順4: 見られる人を決める

Firebase コンソールで、見せたい人の `members` ドキュメントに
`canSeeTeamKpi`（boolean）を `true` で追加します。**付けない人は見られません。**

### 動き

- チームの括りは**原本ではなく `members.team`** を見ます。原本にもチームの列が
  ありますが読みません。原本の組織が変わるたびにアプリの集計が黙って変わる
  のを避けるためです。**異動は `members` を直すだけで反映されます**
- 手配率のチーム集計は、率の平均ではなく **合計手配数 ÷ 合計対応数** です。
  率を平均すると、対応数の少ない人の率が同じ重みで効いてしまいます
- 原本の中に「2026年8月」のような期間の表記があれば拾って画面に出します。
  当月と違っていれば警告を出します（誰かがフィルタを動かした場合に気づくため）

## 工数と残日数（workdays タブ・手入力）

着地見込の計算に使います。**手入力**です。シフトから自動計算もできますが、
半休や研修の扱いが運用で決まるまでは手で入れるほうが早いので、まずこの形。

同期用スプレッドシートに `workdays` タブを作り、こう入れます。

```
A列        B列    C列
氏名       工数   残日数
金兒 胤栄   18     4
根岸 吉寿   14.5   2
三登 有夏   19     3
谷口 豪     20     2
```

- **氏名で照合**します。行の順番が変わっても壊れません
- 見出し行や空行は氏名と一致しないので、自動的に無視されます
- 工数は **0.5刻み**で入ります（半休は 0.5）
- 工数が空の人は着地を計算しません。**0 は入れないでください**
  （`実績 ÷ 0` で無限大になります。空欄なら「未入力」と表示されます）

### 何に使われるか

```
メンバー別の着地 = 実績 ＋ 残日数 × （実績 ÷ 工数）
対応数/1Day     = 対応数 ÷ 工数
```

全体の予実サマリは**暦日**（経過日数 ÷ 総日数）で伸ばすので、workdays が
無くても出ます。工数が要るのはメンバー別の表だけです。

### 確認

`manualSync` 後、`syncStatus/spreadsheet` の `workdaysMemberCount` に人数が
入っていれば取り込めています。0 ならタブ名か氏名の表記を確認してください。

---
## mgmt_kpi の範囲は「実績ブロックの終わりまで」必要

原本の月別タブは、**同じ指標の並びが2回**入っています。

```
行1      見出し（氏名・チーム・拠点）
行2〜37  予算ブロック      ← 第二CCの列は 0 や、人ごとに計算されていない仮の率
行38     実績            ← A列にこの文字が入る
行39〜73 実績ブロック      ← 本物のデータ
```

`mgmt_kpi` の IMPORTRANGE は、**実績ブロックの最後まで**含めてください。

```
A1  =IMPORTRANGE(cfg!B8, cfg!B11&MONTH(TODAY())&"月!A1:B80")
C1  =IMPORTRANGE(cfg!B8, cfg!B11&MONTH(TODAY())&"月!AE1:AV80")
```

行数が足りないと、実績ブロックの下のほう（通話率より下、粗利の内訳など）が
**エラーを出さずに黙って欠けます**。80 行にしておけば当面は足ります。

`A1:B` 側と `AE1:AV` 側の**行数は必ず揃えてください**。ずれるとラベルと値が
対応しなくなります。

### コード側の対応

`readMgmtKpi_` は A列が `実績` の行を探し、**その下だけ**を読みます。
ラベルだけで拾うと予算ブロックを先に掴むためです。

`syncStatus/spreadsheet` の `mgmtActualRow` に、見つけた実績の行番号が入ります。

| 値 | 意味 |
|---|---|
| 38 など | 実績ブロックを見つけている（正常） |
| **0** | 見つかっていない。**予算側を読んでいる可能性がある** |

`0` のときは `missingRows` にも警告が入ります。原本の A列の表記が
`実績` から変わっていないか確認してください。

## 予算比（進捗）

原本の**上の段が予算（月間の目標値）**、下の段が実績です。同じラベル・同じ列
並びなので、`mgmt_kpi` を1つ取り込めば両方そろいます。追加の設定は要りません。

Firestore の `memberKpi/current` に

| フィールド | 中身 |
|---|---|
| `byMember` | 実績 |
| `budgetByMember` | 予算 |

の2つが入ります。`syncStatus` の `mgmtBudgetMemberCount` が 0 なら予算を
拾えていません（`mgmtActualRow` が 0、つまり「実績」の行が見つかっていない
ときは予算と実績を切り分けられないので、予算は空になります）。

### 画面

チームタブのグループタブの右に **実績 / 予算比** の切り替えが出ます。
予算が1件も無いときは切り替え自体を出しません。

予算比では各マスが「達成率＋バー＋実績/予算」になります。

### 判定の基準が2種類あります

| 種類 | 基準 | 理由 |
|---|---|---|
| 件数・金額（合計する指標） | **経過ペース** | 予算は月末までの積み上げ。月半ばに50%でも、日数が半分なら順調 |
| 率（平均・比率） | **100%** | 率は月初から目標に乗っているべきで、日数は関係ない |

バーの縦線が「今日時点であるべき位置」です。件数はペース、率は右端に立ちます。

経過ペースは**暦日**（今日の日付 ÷ 当月の日数）です。営業日にはしていません。
祝日の扱いで揉めるうえ、暦日なら誰でも同じ数字を再現できるためです。

### 予算が無い指標

原本の予算側は、通話率・作業率・待機率・IS追加数などが 0 で入っています
（目標が置かれていない）。これらは **「予算なし」** と表示します。

0 を目標として達成率を出すと無限大になり、0 で埋めると「達成率0%」という
嘘の数字になります。**予算が無いことを、そう表示する**のが正しい扱いです。

なお同期側では 0 のまま Firestore に入れています。ここで捨ててしまうと、
将来「0 が本当の目標」の指標が出てきたときに区別できなくなるためです。

## 月間の通話率・作業率・待機率（任意）

Management Sheet にもこの3つの行はありますが、**第二CCの列は 0.00% のまま**で
実績が入っていません。そのままだと全員0%になるので、`CC_アクション管理` の
月間列から取って上書きします。

### 手順1: ファイルIDを `cfg` に足す

| セル | 中身 |
|---|---|
| `cfg!B12` | CC_アクション管理 のファイルID |

### 手順2: `prod_kpi` タブを作る

同期用スプレッドシートに `prod_kpi` タブを追加し、A1 に貼ります。

```
=IMPORTRANGE(cfg!B12, "個別KPI管理!A1:EZ200")
```

範囲を横に広く取るのは、**月間の列が毎月右へずれる**ためです。

```
6月月間 → B列 ／ 2026年7月 → AK列 ／ 2026年8月 → BU列
```

1か月あたり35〜36列ずつ増えていきます。`EZ` まで取っておけば1年ぶんは入ります。
足りなくなったら右に伸ばしてください。

### 原本の形

同じ形のブロックが縦に積まれています。

```
通話率 | 6月月間 | 2026年7月 | 2026年8月 | 20260727週 | …
全体   |  42.1%  |   42.8%   |   41.9%
第一東京CC …
第二東京CC …
（チーム）
庄司 祐亮 | 46.3% | 45.8% | 45.4%
…
作業率 | …          ← 次のブロック
待機率 | …
```

### 位置ではなく文字で探しています

- **ブロック**は A列の見出し（`通話率` `作業率` `待機率`）で見つけます
- **月の列**は見出し行の中から「`2026年8月`」に一致するセルを探します

そのため列がずれても動き、9月になれば新しく出る「`2026年9月`」の列に
自動で移ります。拠点やチームの行（`全体` `第二東京CC` `野ざらし` など）は
氏名と一致しないので、そのまま無視されます。

### 手順3: 動作確認

`manualSync` 後、`syncStatus/spreadsheet` を見ます。

| フィールド | 意味 |
|---|---|
| `prodBlocks` | 当月の列が見つかったブロック数（**3** が期待値） |
| `prodMemberCount` | 値を取れた人数 |
| `prodMissingBlocks` | 当月の列が見つからなかったブロック名 |

`prodMissingBlocks` に名前が入っているときは、原本にまだ当月の列が
無いか、見出しの表記が変わっています。

> Management Sheet 側の 0.00% が将来埋まったら、`sync.gs` の
> `mergeProdKpi_` の呼び出しを外せば向こうの値に戻ります。

## 日次のメンバー別KPI（任意）

「チーム」タブに **日ごとの対応数・手配数・手配率**を出します。
出どころは各チームのダッシュボードの「今日の状況」ブロックです。

### 手順1: ファイルIDを `cfg` に足す

| セル | 中身 |
|---|---|
| `cfg!B9` | 第二CC 金児チーム ダッシュボードのファイルID |
| `cfg!B10` | 第二CC 庄司チーム ダッシュボードのファイルID |

### 手順2: `daily_kpi` タブを作る

同期用スプレッドシートに `daily_kpi` タブを追加し、A1 に貼ります。
2チームぶんを **`;` で縦に積みます**。

```
={IMPORTRANGE(cfg!B9, "<シート名>!<今日の状況の範囲>");
  IMPORTRANGE(cfg!B10, "<シート名>!<今日の状況の範囲>")}
```

範囲は次の3つが**すべて入る**ように取ります。行や列の位置は見ていないので、
上下に余裕を持たせて構いません。

| 必要なもの | 理由 |
|---|---|
| 「最終更新: YYYY/MM/DD」の行 | 当日ぶんかどうかの判定に使います |
| 列見出しの行（`対応数` `手配数` `手配率` …） | どの列が何の指標かを決めます |
| メンバーの行 | 氏名で `members` と突き合わせます |

チームを増やすときは `;` で足すだけです。コードの変更は要りません。

### 手順3: 動作確認

`manualSync` を実行し、`syncStatus/spreadsheet` を見ます。

| フィールド | 意味 |
|---|---|
| `dailyMemberCount` | その日ぶんを取り込めた人数 |
| `dailyBlocks` | 見つかったブロック数（＝チーム数） |
| `dailyStaleBlocks` | 「最終更新」が当日でなく飛ばしたブロック数 |

`dailyBlocks` が2で `dailyMemberCount` が0なら、氏名が1人も照合できていません。

### 動き

- **1日1ドキュメント**（`memberKpiDaily/YYYY-MM-DD`）。同じ日に何度走っても
  同じIDに上書きするだけなので、毎時実行でも二重計上しません
- **古い日は消しません。** 消す処理は事故のときに取り返しがつかないので置いていません。
  アプリが読むのは新しい35日ぶんだけです
- **「最終更新」が当日でないブロックは書きません。** 祝日や不具合で更新が
  止まったときに、前日の数字が今日として記録されるのが一番まずい間違いなので、
  書かないほうを選んでいます
- **休みの人は空欄のまま**で、キーを持ちません。0 を入れると「対応数0件」として
  平均や合計に混ざるためです。合計の分母から自然に外れます
- 手配率は日ごとに **合計手配数 ÷ 合計対応数**。各人の率の平均にはしません

### ⚠️ 生の依頼データは取り込まないこと

「Daily進捗_CSVData」には**顧客の氏名・電話番号・住所・メールアドレス**を含む
生の依頼データがあります。**あれを IMPORTRANGE してはいけません。**
このアプリのリポジトリは公開されており、防御線は `firestore.rules` 1枚だけです。

集計はスプレッドシートの中で完結させ、アプリには**集計後の数字だけ**渡します。
ダッシュボードの「今日の状況」は集計済みなので、そこを読むのが正しい経路です。

## Google Chat への新着通知（任意）

掲示板・アンケート・フィードに新しい投稿があったとき、Chat のスペースに流します。
`gas/notify.gs` を同じ Apps Script プロジェクトに追加して使います。
**`sync.gs` の認証まわりを使うので、単独では動きません。**

### 手順1: Webhook URL を発行する

1. 通知したい Chat スペースを開く
2. スペース名 → **アプリと統合** → **Webhook を管理**
3. 名前を付けて作成 → 表示される URL をコピー

> ⚠️ **この URL は鍵です。** これを知っている人は誰でもそのスペースに投稿できます。
> リポジトリにもチャットにも貼らず、次の手順で直接スクリプトプロパティに入れてください。

### 手順2: スクリプトプロパティに入れる

Apps Script → ⚙ プロジェクトの設定 → スクリプト プロパティ

| プロパティ名 | 値 |
|---|---|
| `CHAT_WEBHOOK_URL` | 手順1でコピーした URL |

### 手順3: コードを追加する

Apps Script でファイルを追加し（＋ → スクリプト、名前は `notify`）、
[`gas/notify.gs`](../gas/notify.gs) の中身を貼り付けます。

### 手順4: 動作確認と開始

上から順に実行します。

| 関数 | 役割 |
|---|---|
| `checkNotifySetup` | 設定が揃っているかの確認 |
| `sendTestMessage` | スペースに届くかのテスト送信 |
| `resetNotifyWatermark` | **通知の起点を「いま」にする。これより前の投稿は流れません** |
| `installNotifyTrigger` | 5分おきのトリガーを設定 |

`resetNotifyWatermark` を先に実行しないと、初回に既存の投稿がまとめて流れます
（実際には初回実行時に自動で起点を置いて何も送らない作りですが、
明示的に実行しておくほうが確実です）。

### 動き

- **5分おき、8時〜22時台のみ**。深夜に鳴らしても動けないので、
  夜間の投稿は翌朝の最初の実行でまとめて流します
- 1回の実行分は**まとめて1通**にします。5分おきに何通も鳴ると誰も見なくなるため
- 1回で流すのは最大15件。それ以上は「ほか◯件」とだけ出します
- **削除済みの投稿は通知しません**
- 非公開（`visibleTo` で絞った）掲示板の投稿は通知しません。
  スペースは全員が読めるので、題名を流した時点で非公開の意味がなくなるためです
- **Thanks は宛先本人を @メンションします**（次の項）

### Thanks を宛先本人に @メンションする（任意）

一括通知はスペース全員に同じ1通が届くだけなので、**感謝された本人がそれに
気づけません**（最大15件の一覧に紛れます）。Thanks に限り、宛先の名前を
本人への @メンションに差し替えて、その人にだけ Chat の通知が飛ぶようにします。

スペースへの通知そのものは今までどおり流れます。Thanks は人目に触れること
自体が価値なので、本人あてに切り替えてしまうと承認の意味が消えるためです。

#### なぜ一手間かかるのか

Chat は**メールアドレスではメンションできません**。`<users/123456789>` という
数値のユーザーIDが要ります。これは Google 側の名簿から引くしかないので、
**一度だけ**取り込んで `members.chatUserId` に持たせます。
取り込んだ後は Firestore を読むだけになり、名簿のAPIは使いません。

引く経路は2つあり、**どちらか片方を1回実行すれば済みます**。

| 関数 | 使う API | 必要な権限 |
|---|---|---|
| `backfillChatUserIdsViaPeople` | People API（社内ディレクトリ） | **一般ユーザーでOK** |
| `backfillChatUserIds` | Admin SDK（Directory API） | Workspace 管理者のみ |

**まず People API 版を試してください。** 2026-08-20 の導入時は、管理者権限を
持たないアカウントで15名全員分が取れました（同じアカウントで Admin SDK 版は
`Not Authorized to access this resource` で15名全滅しました）。

#### 手順

1. Apps Script の左メニュー **サービス** の ＋ から **People API** を追加する
   （識別子は `People` のまま）
2. `backfillChatUserIdsViaPeople` を実行する
   → `members` の各ドキュメントに `chatUserId` が入ります
3. `checkChatMentions` で全員分入ったかを確認する
4. `sendMentionTest` を実行し、Chat で「@自分の名前」が**青字のメンションに
   なっているか**を目で見る

**手順4は飛ばさないでください。** 取り込んだIDが Chat のメンションに使える
IDと同じである保証はどこにもありません。違っていた場合は `<users/...>` という
生の文字列がそのままスペースに流れます。テスト送信で必ず確かめます。

| 関数 | 役割 |
|---|---|
| `backfillChatUserIdsViaPeople` | 全員分の Chat ユーザーIDを取り込む（べき等） |
| `checkChatMentions` | 誰のIDが未設定かを一覧する |
| `sendMentionTest` | 実行した本人あてにメンションのテストを送る |

#### People API で取れなかった場合

「社内ディレクトリから1人も取得できませんでした」と出るときは、ドメインの
共有設定で無効にされています。その場合は **Admin SDK API**（識別子
`AdminDirectory`）を追加して、**Workspace の管理者アカウント**に
`backfillChatUserIds` を1回だけ実行してもらいます。

どちらも無理なら、`chatUserId` は未設定のままで構いません。
**未設定の人は今までどおり表示名で出るだけ**で、通知そのものは止まりません。
後から入れれば、その時点からメンションに変わります。

#### 対象を広げたいとき

`notify.gs` の `MENTION_TYPES` に投稿の種類を足します（既定は `Thanks` だけ）。
ただし宛先の付いた報告や質問まで鳴らすと、メンションが日常の景色になり、
肝心の Thanks も見られなくなります。まず Thanks だけで様子を見てください。

> ⚠️ この2つの取り込み関数は、`members`（許可リスト）に書き込む唯一の GAS です。
> 書き込みは共通の `runChatIdBackfill_` に寄せてあり、書き換えるのは
> `chatUserId` の1フィールドだけ。`role` や `active` には触れません
> （`updateMask` で明示的に絞っています）。ここを緩めないでください。

### 止めたいとき

Apps Script → 時計アイコン（トリガー）→ `notifyNewPosts` のトリガーを削除。
メンションだけをやめたいときは、`notify.gs` の `MENTION_TYPES` を `[]` にします。

### ログ

同期用スプレッドシートの `_notify_log` タブに、実行時刻・結果・送信件数・
エラーが残ります（直近500件）。
