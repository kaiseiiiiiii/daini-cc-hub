# スプレッドシート同期のセットアップ

シフト・生産性KPI・目標／実績を、会社のスプレッドシートから Firestore へ
1時間おきに取り込む仕組みです。

---

## 構成

```
シフト_CC          ─┐
生産性データ         ├─ IMPORTRANGE ─→ 同期用スプレッドシート ─→ GAS ─→ Firestore ─→ アプリ
手配粗利額データ   ─┘   （読み取り専用）      （自分が所有）
```

**原本には一切書き込みません。** 原本から値を引くのは `IMPORTRANGE` で、これは
読み取りしかできない関数です。GAS は自分が乗っている同期用スプレッドシートしか
見ておらず、原本のファイルIDはコードのどこにも登場しません。書き込む経路が
仕組みとして存在しない構成です。

原本の所有者には**閲覧権限だけ**をもらってください。編集権限は不要です。

### この構成の弱点

`IMPORTRANGE` の値は最大30分ほど遅れることがあります（Google 側の更新間隔）。
1時間おきの同期なので実用上は問題になりませんが、「たった今スプレッドシートに
入れた数字」がすぐには反映されない点は把握しておいてください。

また、権限が切れると `#REF!` になります。その場合 GAS は**書き込まずに中断**し、
アプリ側には「同期が止まっている」警告が出ます。古い数字が最新の顔をして
残り続けることはありません。

## 手順1: サービスアカウントを作る

Firebase コンソールの「新しい秘密鍵の生成」でも動きますが、その鍵は編集者権限を
持っていて強すぎます。**必要最小限の権限だけを持つ専用アカウント**を作ります。

1. https://console.cloud.google.com/iam-admin/serviceaccounts?project=daini-cc-hub
2. 「サービス アカウントを作成」
   - 名前: `daini-cc-hub-sync`
3. ロールを選択 → **「Cloud Datastore ユーザー」**（`roles/datastore.user`）**だけ**
   - Firestore の読み書きのみ。認証・課金・他のGCPリソースには一切触れません
4. 作成後、そのアカウントを開く → 「キー」タブ → 「鍵を追加」→ 「新しい鍵を作成」→ **JSON**
5. ダウンロードされた JSON ファイルを開いて、**中身を全部コピー**

> ⚠️ **この JSON は本物の秘密鍵です。**
> `firebase-config.js` の apiKey とは性質がまったく違います。
> この鍵があれば**セキュリティルールを完全に無視して**全データを読み書きできます。
> リポジトリにも、チャットにも、メールにも貼らないでください。
> 次の手順で GAS のスクリプトプロパティに直接貼り付けたら、
> ダウンロードしたファイルは削除してください。

## 手順2: 同期用スプレッドシートを作る

Google ドライブで新しいスプレッドシートを作り、`第二CC Hub 同期用` などの名前にします。
**所有者は自分**にしてください。

### タブを10個作る

| タブ名 | 中身 |
|---|---|
| `cfg` | 原本のファイルID |
| `shift_prev` | 前月のシフト |
| `shift_cur` | 当月のシフト |
| `shift_next` | 翌月のシフト |
| `productivity` | 生産性KPI |
| `goal_all` | 手配粗利額（全体） |
| `goal_team_a` | 手配粗利額（チームA） |
| `goal_team_b` | 手配粗利額（チームB） |
| `goal_other` | 手配粗利額（その他） |
| `_log` | 実行ログ（GASが自動で作るので手動作成は不要） |

### `cfg` タブ

原本のURLから ID を取り出して入れます。URL の
`https://docs.google.com/spreadsheets/d/【ここがID】/edit` の部分です。

| | A | B |
|---|---|---|
| 1 | シフトのファイルID | `（シフト_CC の ID）` |
| 2 | 生産性のファイルID | `（生産性データ の ID）` |
| 3 | 手配粗利額のファイルID | `（手配粗利額データ の ID）` |
| 4 | 全体のタブ名 | `全体Daily集計` |
| 5 | チームAのタブ名 | `（チームAのタブ名）` |
| 6 | チームBのタブ名 | `（チームBのタブ名）` |
| 7 | その他のタブ名 | `その他` |

> B5・B6 に入れるタブ名はリーダーの姓です。**このリポジトリは公開されている**ため、
> 実際の名前は手順書に書かず、シート側に置いています。
> 手配粗利額データを開いて、タブ名をそのままコピーしてください。

### 各タブの A1 に入れる式

**`shift_cur`**（当月。月が変わると自動で切り替わります）

```
=IMPORTRANGE(cfg!B1, YEAR(TODAY())&"_"&MONTH(TODAY())&"!A1:AH70")
```

**`shift_prev`**（前月）

```
=IMPORTRANGE(cfg!B1, YEAR(EDATE(TODAY(),-1))&"_"&MONTH(EDATE(TODAY(),-1))&"!A1:AH70")
```

**`shift_next`**（翌月。まだ作られていなければ `#REF!` になりますが、それで正常です）

```
=IMPORTRANGE(cfg!B1, YEAR(EDATE(TODAY(),1))&"_"&MONTH(EDATE(TODAY(),1))&"!A1:AH70")
```

**`productivity`**

```
=IMPORTRANGE(cfg!B2, "生産性　集計!A1:M60")
```

> シート名の「生産性」と「集計」の間は**全角スペース**です。半角だと `#REF!` になります。

**`goal_all` / `goal_team_a` / `goal_team_b` / `goal_other`**

タブ名は `cfg` から引くので、この4つはそのまま貼り付けられます。

```
=IMPORTRANGE(cfg!B3, cfg!B4&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B5&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B6&"!A1:K40")
=IMPORTRANGE(cfg!B3, cfg!B7&"!A1:K40")
```

### アクセスを許可する

式を入れた直後は `#REF!` と表示され、セルにカーソルを合わせると
「アクセスを許可」ボタンが出ます。**原本3件それぞれで1回ずつ**押してください。
一度許可すれば、以降は自動で更新されます。

`shift_next` だけは、原本に翌月のシートがまだ無ければ `#REF!` のままです。
これは異常ではありません。

## 手順3: GAS を設置する

1. 同期用スプレッドシートで **拡張機能 → Apps Script**
2. 既定の `コード.gs` の中身を全部消し、リポジトリの
   [`gas/sync.gs`](../gas/sync.gs) の中身を貼り付ける
3. 保存

### スクリプトプロパティを設定する

エディタ左の **⚙ プロジェクトの設定** → 一番下の「スクリプト プロパティ」

| プロパティ名 | 値 |
|---|---|
| `FIREBASE_PROJECT_ID` | `daini-cc-hub` |
| `FIREBASE_SERVICE_ACCOUNT` | 手順1でコピーした JSON **全文**（`{` から `}` まで） |

**この2つ以外に設定は必要ありません。** 鍵も原本のIDも、コード側には一切書きません。

### 動作を確認する

エディタ上部の関数選択で **`checkSetup`** を選んで実行します。
初回は Google の権限確認が出るので許可してください。

「実行ログ」に次のように出れば設定完了です。

```
OK     スクリプトプロパティ FIREBASE_PROJECT_ID
OK     スクリプトプロパティ FIREBASE_SERVICE_ACCOUNT
OK     タブ cfg  3行
OK     タブ shift_prev  67行
OK     タブ shift_cur  67行
#REF!  タブ shift_next（原本にその月が無い場合は正常）
OK     タブ productivity  20行
OK     タブ goal_all  33行
...
OK     アクセストークン取得
OK     members 15名を取得
```

### 手動で1回동かす

**`manualSync`** を実行します。エラーが出なければ、Firestore の
`shifts` / `metrics` / `goals` / `syncStatus` にデータが入ります。
アプリのシフトタブ・実績タブを開いて表示を確認してください。

### トリガーを設定する

**`installTrigger`** を1回だけ実行します。毎時のトリガーが作られます。

Google の仕様上「毎時0分ちょうど」には走らず、その時間内のどこかで実行されます。
時間帯の判定（10時台〜22時台）はコード側で行っているので問題ありません。

---

## 同期の時間帯

| 時刻 | 動き |
|---|---|
| 0時〜9時台 | 何もしない（実績が動かない時間帯。叩いても同じ数字を取り直すだけ） |
| 10時台 | その日の最初の同期 |
| 11時〜21時台 | 毎時同期 |
| 22時台 | **当日分の締め。**実績の最終更新が21時30分なので、これが確定値 |
| 23時台 | 何もしない |

範囲外の時刻ではトリガーは起動しますが、時刻を見て即座に終了します。
ログにも残しません（毎日11行の無意味な行が増えるだけなので）。

---

## 同期が止まったときの見え方

アプリのシフトタブと実績タブに、状態に応じた表示が出ます。

| 状況 | 表示 |
|---|---|
| 正常 | `最終更新 8月7日 14時00分` |
| 10時台で、まだ本日分が同期されていない | 🕙 前日の数字を表示中です。本日分の同期はこれから行われます |
| 11時以降で、本日一度も同期されていない | ⚠️ 本日まだ一度も同期されていません。数字は前日のものです |
| 稼働時間帯で最終更新から3時間以上経過 | ⚠️ 最終更新から◯時間が経過しています |
| 前回の同期が失敗した | ⚠️ 前回の同期が失敗しています |
| 深夜・早朝 | 警告なし（同期しない設計のため） |

**深夜に警告を出さないのが要点です。** 単純な経過時間だけで判定すると、
朝は必ず「12時間更新されていません」と出てしまい、誰も見なくなります。

アプリを開きっぱなしにしていても、5分おきに状態を見直して表示を切り替えます。

## トラブル時の確認場所

**1. 同期用スプレッドシートの `_log` タブ**

実行時刻・結果・所要時間・処理件数・エラー内容が1行ずつ残ります（直近500件）。

| 列 | 内容 |
|---|---|
| 未照合の氏名 | シフト表にいるがメンバーマスタと一致しなかった人数。第二CC以外の拠点の人は当然ここに入るので、0でなくて正常です |

**2. Apps Script の「実行数」画面**

失敗した実行のスタックトレースが見られます。

**3. Firestore の `syncStatus/spreadsheet`**

最終同期時刻、成否、エラー内容、未照合だった氏名の一覧が入っています。

### よくある原因

| 症状 | 原因 |
|---|---|
| `IMPORTRANGE が解決できていません` | 原本の閲覧権限が切れた、または「アクセスを許可」を押していない |
| `members が1件も取得できませんでした` | サービスアカウントのロール不足。Cloud Datastore ユーザーが付いているか確認 |
| 特定の人だけ実績が出ない | メンバーマスタの `fullName` がスプレッドシートの表記と一致していない。`syncStatus` の `unmatchedNames` を確認 |
| `アクセストークンの取得に失敗` | `FIREBASE_SERVICE_ACCOUNT` の JSON が途中で切れている |

## Google Chat への新着通知（任意）

掲示板とアンケートに新しい投稿があったとき、Chat のスペースに流します。
`gas/notify.gs` を同じ Apps Script プロジェクトに追加して使います。
**`sync.gs` の認証まわりを使うので、単独では動きません。**

### 手順1: Webhook URL を発行する

1. 通知したい Chat スペースを開く
2. スペース名 → **アプリと統合** → **Webhook を管理**
3. 名前を付けて作成 → 表示される URL をコピー

> ⚠️ **この URL は鍵です。** これを知っている人は誰でもそのスペースに投稿できます。
> リポジトリにもチャットにも貼らず、次の手順で直接スクリプトプロパティに入れてください。

### 手順2: スクリプトプロパティに入れる

Apps Script → ⚙ プロジェクトの設定 → スクリプト プロパティ

| プロパティ名 | 値 |
|---|---|
| `CHAT_WEBHOOK_URL` | 手順1でコピーした URL |

### 手順3: コードを追加する

Apps Script でファイルを追加し（＋ → スクリプト、名前は `notify`）、
[`gas/notify.gs`](../gas/notify.gs) の中身を貼り付けます。

### 手順4: 動作確認と開始

上から順に実行します。

| 関数 | 役割 |
|---|---|
| `checkNotifySetup` | 設定が揃っているかの確認 |
| `sendTestMessage` | スペースに届くかのテスト送信 |
| `resetNotifyWatermark` | **通知の起点を「いま」にする。これより前の投稿は流れません** |
| `installNotifyTrigger` | 5分おきのトリガーを設定 |

`resetNotifyWatermark` を先に実行しないと、初回に既存の投稿がまとめて流れます
（実際には初回実行時に自動で起点を置いて何も送らない作りですが、
明示的に実行しておくほうが確実です）。

### 動き

- **5分おき、8時〜22時台のみ**。深夜に鳴らしても動けないので、
  夜間の投稿は翌朝の最初の実行でまとめて流します
- 1回の実行分は**まとめて1通**にします。5分おきに何通も鳴ると誰も見なくなるため
- 1回で流すのは最大10件。それ以上は「ほか◯件」とだけ出します
- **削除済みの投稿は通知しません**
- フィード（サンクス）は通知しません。件数が多くスペースが埋まるためです

### 止めたいとき

Apps Script → 時計アイコン（トリガー）→ `notifyNewPosts` のトリガーを削除。

### ログ

同期用スプレッドシートの `_notify_log` タブに、実行時刻・結果・送信件数・
エラーが残ります（直近500件）。

## 権限のまとめ

| 対象 | 誰が | 何ができるか |
|---|---|---|
| 原本3件 | 自分（閲覧権限） | 読むだけ。IMPORTRANGE 経由 |
| 同期用スプレッドシート | 自分（所有） | GAS が読み書き |
| Firestore の `shifts` / `goals` / `metrics` / `syncStatus` | サービスアカウント | 書き込み |
| 同上 | アプリの利用者 | **読み取りのみ**（`firestore.rules` で write を全面禁止） |
